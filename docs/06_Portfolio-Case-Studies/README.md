## Format

Each case study follows the same structure, so it can be read for reasoning rather than
narrative:

**Problem** → **Design constraints** → **Decision** → **Implementation status** →
**Validation status** → **Lessons learned** → **Next phase**

## Honesty rule

Case studies state **Planned / Documented** where that is the truth, and only claim
**Implemented / Tested / Validated** where internal evidence supports it.

**No case study here currently claims a result above _Documented_**, because no infrastructure
work has reached that maturity. Writing up a design as though it were a deployment would be the
exact failure this project's governance model exists to prevent.
